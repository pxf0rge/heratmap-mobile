# فاز ۹ — تست، CI و انتشار

**وضعیت:** ⬜
**وابستگی:** فازهای ۱ تا ۸
**ارزش:** پروژه هیچ تستی ندارد و هنوز با `applicationId` پیش‌فرض و امضای دیباگ ساخته می‌شود.
تا این دو حل نشود، انتشار در Google Play ممکن نیست و هر تغییر بعدی ریسک شکستن دارد.

## اهداف

1. **تست واحد:** پارسرها (`working_hours`، split تصویر، نرمال‌سازی متن فارسی)، کش/retry،
   نگاشت مدل‌ها از `Map` ناقص/خراب.
2. **تست ویجت:** اسپلش، تب‌ها، حالت‌های خالی/خطا با مخزن جعلی (بدون شبکه).
3. **تست قرارداد داده:** یک تست اختیاری که با کلید عمومی به Supabase می‌زند و اگر ستون‌ها
   تغییر کرده باشند هشدار می‌دهد (برچسب `integration`، به‌صورت پیش‌فرض در CI خاموش).
4. **CI:** گردش‌کار GitHub Actions برای `flutter analyze` + `flutter test` روی هر PR
   (با کش pub، و آینه‌ی pub در صورت نیاز شبکه).
5. **آماده‌سازی اندروید:** `applicationId` واقعی، امضای release با کی‌استور خارج از ریپو،
   `minSdk`/`targetSdk` مناسب، آیکون و اسپلش بومی، نوار وضعیت/ناوبری.
6. **پایش خطا:** افزودن گزارش‌گیری کرش (نیازمند بسته‌ی جدید — با تأیید کاربر) یا حداقل
   ثبت ساخت‌یافته‌ی خطاها به‌همراه نسخه‌ی اپ و زبان.
7. **انتشار:** نسخه‌گذاری معنادار، تغییرات هر نسخه، سیاست حفظ حریم خصوصی،
   فهرست فروشگاه (توضیحات fa/ps/en، اسکرین‌شات، دسته‌بندی)، بسته‌ی نهایی AAB.

## خروجی‌ها

- `test/` (واحد + ویجت) و `integration_test/` اختیاری
- `.github/workflows/ci.yml`
- `android/app/build.gradle.kts` + `key.properties.example` + `docs/release/android-release.md`
- `docs/release/store-listing.md`، `CHANGELOG.md`

## معیار پذیرش

- [ ] `flutter test` سبز و پوشش لایه‌ی داده + پارسرها.
- [ ] CI روی PRهای بعدی اجرا و سبز می‌شود.
- [ ] `flutter build appbundle --release` با امضای واقعی و `applicationId` درست موفق شود.
- [ ] نصب روی یک دستگاه واقعی و عبور از چک‌لیست دستی انتشار (فهرست در سند فاز).

## چک‌لیست دستی انتشار (پیش‌نویس)

- [ ] نصب تازه → اجازه‌ی موقعیت → نقشه کار کند.
- [ ] حالت پرواز → اپ باز شود و داده‌ی کش‌شده/پیام آفلاین درست باشد.
- [ ] تغییر زبان در میانه‌ی استفاده → بدون کرش.
- [ ] چرخش/تغییر اندازه‌ی فونت سیستم → بدون سرریز چیدمان.
