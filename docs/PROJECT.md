# شهرک صنعتی هرات (HeratMap)

> این سند، «توصیف پروژه» است: هدف، کاربران، قابلیت‌ها، معماری و قرارداد داده.
> از روی کد فعلی + تصمیم‌های ثبت‌شده‌ی پروژه (انتقال بک‌اند به **Supabase**) بازسازی شده است.
> اگر نسخه‌ی رسمی و متنی توصیف پروژه در دسترس است، همان باید این فایل را تکمیل/اصلاح کند.

---

## ۱. چشم‌انداز

یک اپلیکیشن موبایل (Flutter) برای **راهنمای شهرک صنعتی هرات**: کارآفرین، بازدیدکننده یا راننده‌ی
باری بتواند روی نقشه ببیند کدام شرکت در کدام «فاز» قرار دارد، آن را جستجو کند، مسیر برود،
تماس بگیرد و اطلاعات تماس را به اشتراک بگذارد — حتی با اینترنت ضعیف.

**جمله‌ی مأموریت:** «پیدا کردن هر شرکت شهرک صنعتی هرات در کمتر از سی ثانیه.»

## ۲. کاربران و سناریوها

| کاربر | سناریو اصلی |
|---|---|
| صاحب کالا / خریدار | «شرکت تولید نوشیدنی کجاست؟» → جستجو → جزئیات → مسیریابی |
| راننده/حمل‌ونقل | نقشه + نزدیک‌ترین شرکت‌ها + مسیریابی |
| بازدیدکننده/مقام محلی | مرور فازها و تعداد شرکت‌های هر فاز |
| ادمین داده (فعلاً بیرون از اپ) | افزودن/ویرایش شرکت‌ها و تصاویر در Supabase |

## ۳. دامنه‌ی نسخه‌ی ۱.۰

### داخل دامنه
- نقشه‌ی تعاملی با پین شرکت‌ها روی OpenStreetMap (بدون کلید API).
- کش کاشی نقشه (flutter_map_tile_caching) برای استفاده‌ی آفلاین.
- Bottom sheet کشویی با «نزدیک‌ترین شرکت‌ها» + فاصله‌ی محاسبه‌شده.
- جستجو روی نام/آدرس/دسته‌بندی + فیلتر فاز.
- تب فازها: کارت هر فاز + تعداد شرکت‌ها → لیست شرکت‌های آن فاز.
- جزئیات شرکت: گالری تصویر، اطلاعات تماس، تماس، اشتراک‌گذاری، مسیریابی.
- سه‌زبانه: دری (fa، پیش‌فرض) / پشتو (ps) / انگلیسی (en) با پشتیبانی RTL.
- تنظیمات: زبان، نسخه، درباره/تماس.

### خارج از دامنه (نسخه‌های بعد)
حساب کاربری و ورود، ثبت‌نام شرکت توسط خود شرکت، پنل وب ادمین، اعلان‌ها، نظردهی،
نقشه‌ی داخلی ساختمان‌ها، پرداخت.

## ۴. معماری

```
lib/
├─ main.dart                 نقطه‌ی ورود: GetStorage → Supabase → FMTC → GetMaterialApp
├─ core/                     AppConfig، DataStateMixin، نرمال‌سازی متن، زمان نسبی، ساعت کاری، لینک‌ها
├─ data/
│  ├─ provider/app_provider  دسترسی مرکزی به SupabaseClient
│  ├─ endpoints.dart         نام جدول‌ها
│  ├─ result.dart            DataResult/DataSuccess/DataFailure + DataError تایپ‌دار
│  ├─ retry.dart             withRetry (backoff+jitter) + SingleFlight
│  ├─ cache/                 KeyValueStore + LocalCache + SearchHistoryStore + FavoritesStore
│  ├─ models/                FactoryModel، PhaseModel (نگاشت امن + toMap)
│  └─ repository/            FactoryRepository، PhaseRepository (شبکه ⇄ کش، بدون پرتاب استثنا)
├─ routes/                   GetX routes/pages
├─ screens/<feature>/        screen + binding + controller + widgets
├─ l10n/app_translations     کلیدهای رشته + سه دیکشنری
├─ theme/ values/ widgets/   توکن‌های طراحی
└─ gen/                      assets.gen / fonts.gen
supabase/                    config.toml + migrations/ + seed.sql   (فاز ۱)
docs/                        این سند + ROADMAP + فایل هر فاز
```

- **State management:** GetX (binding/controller/Obx).
- **ذخیره‌سازی محلی:** GetStorage (کش کارخانه‌ها/فازها + زبان انتخابی).
- **بک‌اند:** Supabase (Postgres + Storage). بدون Auth در نسخه‌ی ۱.
- **نقشه:** flutter_map + OSM + FMTC؛ geolocator + permission_handler برای موقعیت.

## ۵. قرارداد داده (Data Contract)

### جدول `phases`
| ستون | نوع | توضیح |
|---|---|---|
| `id` | bigint PK | شناسه |
| `name` | text | نام نمایشی که **همان مقدار ستون `factories.phase`** است، مثل `فاز 1` |
| `number` | int | ترتیب نمایش (صعودی) |
| `image` | text (nullable) | آدرس کامل تصویر در Storage |

### جدول `factories`
| ستون | نوع | توضیح |
|---|---|---|
| `id` | bigint PK | شناسه |
| `name` | text | نام شرکت |
| `category` | text | دسته‌بندی، مثل `برق و قدرت` |
| `phase` | text | نام فاز (FK منطقی به `phases.name`) |
| `lat`, `lon` | float8 | مختصات WGS84؛ صفر = نامعتبر |
| `address` | text | آدرس متنی |
| `phone` | text | شماره تماس |
| `working_hours` | text | مثل `7 - 7` |
| `description` | text | توضیحات |
| `image` | text | **چند آدرس با `\|` جدا می‌شوند** (`url1\|url2`) |

### Storage
- باکت عمومی `images`؛ آدرس عمومی:
  `https://<ref>.supabase.co/storage/v1/object/public/images/<file>`

### قواعد اعتبارسنجی (فاز ۸ به‌صورت خودکار اعمال می‌کند)
1. `name` بدون فاصله‌ی ابتدایی/انتهایی.
2. مختصات داخل محدوده‌ی شهرک: lat ∈ [34.188, 34.218]، lon ∈ [62.200, 62.230].
3. `image` بدون تکرار، بدون `|` انتهایی/خالی.
4. `phase` باید با یکی از مقادیر `phases.name` مو‌به‌مو یکسان باشد (شماره‌ها **لاتین**: `فاز 1`).

## ۶. وضعیت فعلی (سپتامبر ۲۰۲۶)

- اپ در ظاهر کامل است و `flutter analyze` سبز است (بدون هیچ warning/info).
- لایه‌ی داده بازنویسی شده (فاز ۲): نتیجه‌ی تایپ‌دار، کش نسخه‌دار، retry با backoff،
  تک‌پرواز، خطاهای ترجمه‌شو و جستجوی نرمال‌شده‌ی فارسی/پشتو.
- تب نقشه بازسازی شده (فاز ۳): خوشه‌بندی پین‌ها، محدوده‌ی مشتق از داده، Recenter واقعی.
- تب جستجو بازسازی شده (فاز ۴): جستجوی دو مسیره (سرور `ilike` + اجتماع محلی)، debounce
  ۳۵۰ms، چیپ‌های فاز پویا با شمارش، تاریخچه‌ی جستجو روی دستگاه، اسکلتون و حالت‌های
  خالی/خطای کامل.
- صفحه‌ی جزئیات شرکت بازسازی شده (فاز ۵): گالری با شمارنده و بزرگ‌نمایی، نشانگر باز/بسته
  بر اساس ساعت کاری و ساعت کابل، نشان‌کردن شرکت (ذخیره روی دستگاه + فیلتر در جستجو)،
  رونوشت/تماس/مسیریابی با اعتبارسنجی داده، و اشتراک‌گذاری چندزبانه.
  **۱۳۴ تست واحد سبز** و `flutter analyze` بدون هیچ warning/info.
- بک‌اند Supabase **وصل است** (خواندن عمومی کار می‌کند) و `scripts/supabase_smoke.sh` هر ۷ چک را پاس می‌کند.
- **داده تقریباً خالی است:** ۲ فاز و ۱ شرکت. `phases.image` تهی است.
- **باگ اسکیمای زنده:** کلید خارجی اشتباه `factories_id_fkey` روی `factories.id → phases.id` وجود دارد؛
  نتیجه این‌که هر درج شرکت جدید خطای `23503` می‌دهد و عملاً تعداد شرکت‌ها به تعداد فازها محدود شده است
  (به احتمال زیاد علت این‌که فقط ۱ شرکت دارید همین است). اصلاح: `migrations/20260911000001_init_schema.sql`.
- چند ستون متنی در جدول زنده `NOT NULL` **بدون مقدار پیش‌فرض** هستند؛ درج ردیف ناقص را با `23502` رد می‌کنند.
  migration برای همه مقدار پیش‌فرض می‌گذارد.
- مشکلات داده‌ی موجود: فاصله‌ی ابتدایی در نام (`" زلال موفق"`)، آدرس تصویر تکراری در `image`.
- `android` هنوز `applicationId` پیش‌فرض دارد (فاز ۹).
- جستجو در حال حاضر کل دیتاست کش‌شده را فیلتر می‌کند (همان لیستی که نقشه هم استفاده
  می‌کند)؛ با رشد داده به چند هزار ردیف باید صفحه‌بندی/`limit` اضافه شود.
- ستون `working_hours` متن آزاد است (`7 - 7`). پارسر فعلی بازه‌ی ساده را می‌فهمد؛ اگر
  داده‌ی چندبازه‌ای یا «تعطیل جمعه» لازم شد، باید قرارداد داده دقیق‌تر شود (فاز ۸).
- `supabase login` انجام نشده؛ اعمال migration فعلاً از طریق SQL Editor داشبورد انجام می‌شود.
